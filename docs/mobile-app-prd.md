## 1. 文档目的

本文定义 AgentPort 配套移动 App 的 v1.0 产品范围、用户场景、功能边界、非功能要求、阶段门禁与验收标准，作为后续交互设计、技术设计和任务拆分的共同输入。

本轮不确定具体移动框架、协议编码、代码目录结构或详细开发任务；这些技术选择不得改变本文确认的安全边界、功能范围和验收结果。

## 2. 产品目标

AgentPort Mobile 让个人用户在离开电脑后，通过自己配置的 SSH 或 Mosh 连接一台或多台安装了 AgentPort 的电脑，查看、接续和控制 AgentPort 中的 Agent Session，并完成桌面端基线所提供的全部业务能力。

移动端不是桌面界面的缩小版。它应针对触屏、窄屏、移动网络和系统后台限制重新组织信息与交互，同时保持业务能力和安全语义等价。

### 2.1 核心价值

1. 在手机上及时发现哪些 Agent 正在工作、等待输入、已完成或异常退出。
2. 从桌面端无缝接续 Session，完成文本输入、结构化提问、审批、终端操作、中断、停止和恢复。
3. 从一部手机管理多台个人电脑上的项目、Session、Worktree、Git、文件和 AgentPort 设置。
4. 不引入 AgentPort 账号、官方云、中继或遥测，继续保持本地优先和用户自管连接。

### 2.2 非目标

- 团队共享、组织、成员、角色或协作权限。
- AgentPort 官方账号、云同步、官方中继、离线推送或遥测。
- 替代完整 IDE 或提供通用代码编辑器。
- SSH 本地/远程端口转发或动态 SOCKS 代理。
- Wake-on-LAN 或公网唤醒服务。
- App Store、Google Play 发布或预签名安装包。

## 3. 目标用户与环境

### 3.1 用户

- 单个用户连接自己有权登录的多台电脑。
- 用户了解 SSH 主机、端口、用户名和认证凭据的基本概念。
- 复杂网络用户可配置一个 SSH 跳板机；App 不实现任意多级跳板或完整 OpenSSH 配置语义。

### 3.2 正式支持平台

| 类别 | v1.0 支持范围 |
|---|---|
| 手机 | iOS 16+、Android 10+ |
| 平板 | 可运行自适应布局，但不承诺平板多栏、键鼠或专项体验 |
| 电脑端 | macOS 13+、Ubuntu 22.04/24.04 |
| 其他桌面发行形态 | Fedora、Arch、AppImage 尽力兼容，不纳入正式验收 |
| 分发 | 开源源码、双端构建说明和团队签名配置模板 |

### 3.3 规模基线

- 最多 5 台电脑同时保持在线连接。
- 聚合视图按合计 100 个 Session 验收。
- App 启动后不自动连接全部主机；用户逐台发起连接。
- 已由用户连接的多台主机可以同时在线，并进入聚合状态视图。

## 4. 产品原则与硬边界

1. **SSH 账户即授权主体**：SSH 登录成功后，移动端获得该系统用户下 AgentPort 的完整操作权限，不增加设备配对、AgentPort 口令或操作提权层。
2. **不新增公网服务**：Remote Bridge 不监听公网端口，通过 SSH/Mosh 会话按需启动。
3. **GUI 不拥有 Session**：电脑端 AgentPort GUI 无需运行；只要电脑、SSH 和 AgentPort Core/Host 可用，移动端即可工作。
4. **不猜测交互语义**：只有高置信结构化事件才能转换为移动卡片；无法可靠识别时必须进入完整终端处理。
5. **不静默重放输入**：网络边界不清时，未确认发送结果的输入不得自动重放。
6. **不扩大正文留存**：手机默认不持久化 Session 正文和终端输出。
7. **保留桌面安全语义**：停止、删除、覆盖、恢复、危险 Git 操作、Secret 和备份等操作沿用或加强桌面端确认与失败原子性。
8. **能力协商优先**：移动端依据 Bridge 声明的协议版本和能力工作，不根据版本号猜测功能。

## 5. 关键用户流程

### 5.1 添加并首次连接主机

1. 用户添加主机名称、地址、端口、用户名和连接方式。
2. 可选择直连或一个 SSH 跳板机。
3. 用户选择密码或密钥认证；密钥可在 App 内生成 Ed25519，或导入常见 OpenSSH 私钥。
4. 首次连接展示服务端主机密钥指纹，由用户确认后保存。
5. App 通过 SSH 启动内置 Remote Bridge，完成协议和能力协商。
6. 指纹后续变化时连接被阻断，用户必须明确移除旧信任后重新确认。

### 5.2 从聚合首页处理等待事项

1. 首页展示已保存主机及最后已知状态。
2. 用户手动连接需要使用的主机。
3. 已连接主机的运行中、等待输入、未读、已完成和异常 Session 聚合显示，并始终标注所属主机和项目。
4. 用户进入 Session，以对话视图阅读；必要时切换完整终端。
5. 输入作为一个原子批次提交；若其他客户端正在输入，界面提供瞬时状态提示。

### 5.3 网络切换与恢复

1. SSH 连接中断后 App 自动重连，并从已确认的事件/日志游标续接。
2. 已确认发送成功的输入不重复；结果未知的输入显示为待用户处理，不静默重发。
3. Mosh 实时通道在网络切换后漫游；SSH 控制通道独立恢复。
4. 重连失败时保留最后已知状态并标记时间和“非实时”，不得把缓存状态显示为在线事实。

### 5.4 从手机向 Agent 提供文件

1. 用户从系统文件选择器或相册选择文件。
2. 用户选择远端项目目录或临时目录；覆盖必须确认。
3. App 通过 SFTP 完成上传和完整性校验。
4. 上传成功后，用户确认将远端路径作为一个原子输入批次发送给目标 Session。
5. 上传失败时不得发送不存在或不完整的路径。

## 6. 功能需求

### 6.1 主机与连接配置

| ID | 要求 |
|---|---|
| HOST-01 | 支持保存、编辑、复制、排序、启用/停用和删除多台主机配置。 |
| HOST-02 | 配置包含显示名、地址、端口、用户名、SSH/Mosh 模式、认证凭据引用、可选单级跳板机和 Mosh UDP 参数。 |
| HOST-03 | 支持 IPv4、IPv6、主机名和非默认 SSH 端口。 |
| HOST-04 | App 不自动连接全部主机；用户手动连接后可同时保持最多 5 台在线。 |
| HOST-05 | 离线主机展示最后连接时间、最后错误和最后已知摘要，并明确标记信息可能过期。 |
| HOST-06 | 主机配置可通过加密文件导入导出；私钥和密码不得包含在配置导出中。 |
| HOST-07 | 删除主机配置时允许用户选择是否同时删除其凭据引用和已保存主机指纹。 |
| HOST-08 | 不提供 Wake-on-LAN、后台轮询全部主机或自动安装远端依赖。 |

### 6.2 SSH 认证与主机信任

| ID | 要求 |
|---|---|
| AUTH-01 | 支持密码和 SSH 私钥认证。 |
| AUTH-02 | 支持生成 Ed25519 密钥、导入常见 OpenSSH 私钥、私钥口令解锁及一把密钥绑定多台主机。 |
| AUTH-03 | 密码、私钥和私钥口令只能保存于 iOS Keychain/Android Keystore 支持的安全存储，不得进入普通数据库、日志、崩溃报告或配置导出。 |
| AUTH-04 | 使用凭据前通过 Face ID、Touch ID 或 Android 生物识别解锁；不额外启用整 App 锁。 |
| AUTH-05 | 首次连接采用 TOFU：展示主机指纹并要求确认；主机密钥变化时强制阻断。 |
| AUTH-06 | v1.0 不支持 FIDO/硬件密钥、SSH Agent 转发、多级 ProxyJump、任意 ProxyCommand 或完整 OpenSSH `Match` 语义。 |
| AUTH-07 | App 进入系统任务切换器时不主动遮蔽当前画面。 |
| AUTH-08 | 一次成功生物识别仅创建当前 App 进程内、当前主机连接范围的凭据使用租约。短时后台和该连接的自动重连可复用租约；用户主动断开、修改凭据/主机配置或 App 进程终止后租约失效，下次连接必须重新验证。凭据明文不得因租约落盘。 |
| AUTH-09 | 使用跳板机时，跳板机和目标机分别维护主机密钥与信任记录；任一跳的首次指纹都需确认，任一指纹变化都在继续该跳前阻断。 |

### 6.3 Remote Bridge 与协议

| ID | 要求 |
|---|---|
| BRIDGE-01 | Remote Bridge 随 AgentPort 桌面安装包内置，并可通过 SSH 非交互命令启动；不要求 GUI 正在运行。 |
| BRIDGE-02 | Bridge 不监听公网端口，不安装独立常驻服务，不要求用户另装 AgentPort 组件。 |
| BRIDGE-03 | 建连时交换协议版本、AgentPort 版本、平台和能力集合。 |
| BRIDGE-04 | 兼容能力按协商结果降级；协议不兼容时禁止危险或语义不明的操作并给出明确升级指引。 |
| BRIDGE-05 | 请求具有唯一标识和明确完成状态；可重试的读取与不可安全重试的写入必须可区分。 |
| BRIDGE-06 | 实时状态、终端输出和历史分页带单调游标，使重连能够续接、去重和识别数据缺口。 |
| BRIDGE-07 | Bridge 必须支持多个桌面/移动客户端同时订阅同一 Session。 |
| BRIDGE-08 | 所有输入批次在单个 Session 内原子排队，批次之间按服务端接收顺序写入 PTY。 |
| BRIDGE-09 | 不在 SSH/Mosh 传输加密之上增加 AgentPort 应用层加密或配对密钥体系。 |
| BRIDGE-10 | 不新增手机远程操作审计表或输入正文审计。现有 AgentPort 状态和业务事件仍按原规则产生。 |

### 6.4 SSH 与 Mosh 传输

| ID | 要求 |
|---|---|
| NET-01 | SSH 模式承载 Bridge 控制、事件、终端和文件操作。 |
| NET-02 | Mosh 模式由 Mosh 承载实时终端，由 SSH 辅助通道承载主机、列表、配置和控制 API。 |
| NET-03 | SSH 启动和控制通道可经过单级跳板机。Mosh UDP 必须由手机直达目标主机；不可达时明确建议切换 SSH。 |
| NET-04 | 远端缺少 `mosh-server` 时检测并显示 macOS/Ubuntu 安装及 UDP 防火墙指引，不自动安装。 |
| NET-05 | SSH/Mosh 自动重连使用有限退避并可由用户取消。 |
| NET-06 | SSH 结果未知的写操作不得自动重放；Mosh 的终端同步不得造成重复命令提交。 |
| NET-07 | 不支持 SSH 端口转发或 SOCKS 代理。 |

### 6.8 独立 SSH/Mosh Shell

| ID | 要求 |
|---|---|
| TERM-01 | 每台主机可创建普通 SSH 或 Mosh Shell，不要求先进入 AgentPort Session。 |
| TERM-02 | 支持多标签、重命名、关闭、横竖屏、特殊键栏、外接键盘和终端搜索。 |

## 7. 非功能需求

### 7.1 性能

| ID | 指标 |
|---|---|
| PERF-01 | 在第 10 节两个最低版本参考设备档上，各执行 10 次清进程冷启动；从进程启动到主机列表可操作的 p95 不超过 3 秒。 |
| PERF-02 | 对已保存主机连续执行 20 次连接操作，点击后进入可取消、可读的连接状态的 p95 不超过 1 秒；认证完成时间单独记录，不把公网 RTT 计入 App 额外延迟。 |
| PERF-03 | 排除网络 RTT 后，以不少于 100 个输入批次测量从 App 提交至本地传输层写入，额外延迟 p95 不超过 100 ms。 |
| PERF-04 | 连续 10 分钟以 1 MiB/min 输出终端数据并同时执行输入、滚动和 Session 切换；超过 50 ms 的 UI 帧不多于 1%，不得出现超过 500 ms 的主线程停顿。 |
| PERF-05 | 在 5 台在线主机、合计 100 个 Session 的固定数据集上各执行不少于 100 次筛选和导航；操作响应 p95 不超过 200 ms，列表滚动中超过 50 ms 的 UI 帧不多于 1%。 |
| PERF-06 | 每次发布验收报告必须记录宿主机硬件、系统版本、工具链、模拟设备参数、数据集、预热方式和原始测量结果；阈值须在 iOS 与 Android 参考档分别满足，不得合并平均。 |

### 7.2 可靠性

- 读取类请求可安全重试并去重。
- 写操作必须报告已完成、明确失败或结果未知三种状态。
- 断线续接不得制造重复输入、重复停止、重复删除或重复 Git 写操作。
- 所有远端导出、上传、备份和恢复遵循现有原子性与预检规则。
- App 崩溃、退出或失去网络不得停止电脑端 AgentPort Session。

### 7.3 无障碍

- 主机、Session、消息、表单、确认框、设置和关键控制流程支持 VoiceOver/TalkBack。
- 支持系统动态字号、足够对比度、减少动效和可访问名称。
- 完整终端可记录屏幕阅读器限制，但必须提供复制、搜索、字号和对话视图替代路径。

### 7.4 国际化与视觉

- v1.0 支持简体中文 `zh-CN` 与英语 `en-US`。
- 支持跟随系统、浅色和深色主题，以及 AgentPort 终端主题。
- 品牌与状态语义保持一致，布局和导航按移动端重新设计。

## 8. 安全验收

1. 抓取应用日志、普通数据库、配置导出和诊断产物，确认不存在密码、私钥、私钥口令或 Secret 原值。
2. 首次主机指纹必须由用户确认；模拟指纹变化后连接必须在启动 Bridge 前阻断。
3. 未通过 SSH 认证的连接不能发现 AgentPort 数据或 Bridge 能力。
4. Bridge 不产生公网监听端口，进程只在已认证传输上下文中工作。
5. SFTP 删除、覆盖和权限修改必须有明确目标确认；权限拒绝不得被客户端绕过。
6. 网络中断时，结果未知的输入、Git 写操作、删除和停止不得自动重放。
7. 配置导出解密后仍不得包含私钥和密码。
8. 移除主机信任后，下次连接必须重新确认指纹。

## 10. 验收环境边界

根据已确认范围，v1.0 只要求模拟器/仿真器验收，不要求真机：

- iOS：最低版本参考档为 iPhone 14 / iOS 16 模拟器；另覆盖当前工具链可用的最新 iOS 模拟器。
- Android：最低版本参考档为 Pixel 5 / Android 10（API 29）仿真器；另覆盖当前稳定 Android 仿真器。
- 电脑端：macOS 13+ 测试环境、Ubuntu 22.04 和 24.04 测试环境。
- 网络：直连、单级跳板、延迟/丢包/断网/地址切换模拟、Mosh UDP 可达与不可达。
- 性能宿主：不预设某一开发者电脑；每次发布冻结并记录同一台宿主机及其硬件/系统/工具链，iOS 与 Android 都在该记录环境中独立满足第 7.1 节绝对阈值。

仅模拟器验收无法充分证明真实蜂窝网络切换、系统后台冻结、生物识别、安全存储、外接键盘和 Mosh UDP 在真机上的行为。该剩余风险不阻止本文定义的 v1.0 验收，但必须在发布说明中披露。

## 11. 分阶段交付与门禁

### 阶段 0：可行性原型

- 在 iOS/Android 模拟器上验证 SSH、Mosh、PTY 终端渲染、Bridge 双向事件和系统安全存储接口。

- 输出风险结论；若纯模拟器不能验证某项，必须记录替代证据和剩余风险，不能宣称真机通过。

**门禁**：能连接一台测试主机、列出 Session、接收实时输出、发送一个原子输入批次并重连去重。

- 主机配置、密码/密钥、TOFU、单级跳板、协议协商、能力降级和版本提示。

**门禁**：AC-01、AC-02、AC-03、AC-16、AC-19、AC-20 通过。

**门禁**：AC-04、AC-05、AC-06、AC-12 通过。

## 12. 主要风险与已接受取舍

| 风险 | 已确认取舍 |
|---|---|
| 完整桌面等价使 v1.0 范围很大 | 允许分阶段开发，但 v1.0 最终统一达标，不先公开功能缩水版 |
| Mosh 不提供通用 TCP 转发 | 采用 Mosh 实时终端 + SSH 控制双通道；UDP 必须直达目标 |
| 移动后台限制连接和通知 | 只承诺前台和短时后台；不建设离线推送 |
| SSH 账户权限过大 | 明确将 SSH 账户视为完整授权主体，不增加配对或二次口令 |
| SFTP 可访问整个账户权限范围 | 保留服务端权限，危险文件操作确认，不增加目录沙箱 |
| 多客户端误输入 | 输入按批次原子排队并显示瞬时输入状态，不引入单一控制权 |
| 无审计降低可追溯性 | 不新增远程操作审计，也不记录输入正文 |
| 无 App 锁、后台画面可见 | 依赖系统锁屏和凭据生物识别，不主动遮蔽任务切换器 |
| 仅模拟器无法覆盖真实设备差异 | 接受为 v1.0 验收边界，在发布说明披露剩余风险 |
| 无账号和云限制同步能力 | 主机配置仅本机保存，通过加密文件手动迁移，凭据不导出 |
