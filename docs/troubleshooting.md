# AgentPort 故障排查

本文按"现象 → 原因 → 处理"列出 AgentPort 常见问题与对应解决办法；覆盖 PRD 7.4 的全部错误状态及常见的环境类问题。排查时建议先打开诊断中心（Host 列表、CLI 能力快照、复制诊断摘要）。

## 找不到 CLI（未安装或已移动）

- **现象**："找不到 Kimi Code：原路径已失效。"或 Agent 标记为"不可用"。
- **原因**：CLI 未安装、被卸载、升级后路径变化，或版本探测超时/崩溃。
- **处理**：
  1. 在终端确认命令存在：`command -v claude codex kimi`；
  2. 在设置页对该 Agent 点"重新检测"；
  3. 路径已变化时用"选择文件"手动指定新的绝对路径；
  4. 探测超时的 CLI 会被标记"不可用"，可"复制诊断信息"后修复再重新检测。某个 Agent 不可用不阻塞其他 Agent。

## CLI 带 macOS 隔离属性（Gatekeeper）导致探测超时、会话空白

- **现象**：某 Agent 长期"不可用"，探测原因是 `--version` 超时；从 AgentPort 打开该 Agent 的会话后终端一直没有内容（进程在，但没有任何输出）。同样地，在终端里手敲该命令也不返回。
- **原因**：Homebrew 等下载渠道会给 CLI 打上 `com.apple.quarantine`（落在二进制上或其安装目录上）。macOS 在进程进入 `main` 之前先做 Gatekeeper 评估，评估完成前进程停在动态链接阶段——既不输出也不退出，AgentPort 的只读探测只能看到 5 秒超时（本机 2026-09 实测首次评估耗时 5 分 41 秒才放行，之后同一文件被标记为已放行，启动变回即时）。macOS 的评估服务卡住时（例如 `spctl --master-disable` 关闭了评估），等待时间可能长到无法接受。
- **处理**：
  1. 确认属性：`xattr -r "$(command -v codex)"`（路径也会出现在探测失败原因里）；
  2. 清理二进制及其安装目录：`xattr -dr com.apple.quarantine /opt/homebrew/Caskroom/codex`（Apple 签名的 App 可用 `xattr -cr`）；
  3. 回到设置页/诊断中心点"重新检测"——清理后不再需要评估，`--version` 立即返回；此后从 AgentPort 启动的会话会正常渲染。
  4. 若清理后仍超时：这条路径上可能留下了未完成的评估记录，换用新的路径（例如 `brew upgrade --cask <cask>` 装到新的版本目录）或重启系统后再试。探测超时的原因里现在会直接写明隔离属性与待清理路径，不再只有一个裸超时。
- **注意**：`brew upgrade` / `brew reinstall` 会重新带上隔离属性，升级后请重复第 2 步。

## GUI 的 PATH 与终端不一致

- **现象**：终端里 `claude`/`kimi` 可用，但 AgentPort 探测不到。
- **原因**：从 Finder/桌面环境启动的 GUI 不会继承 `~/.zshrc`、`~/.bashrc` 中的 PATH。
- **处理**：首次启动向导会依次读取系统 PATH、登录 Shell 的 PATH 和常见安装目录；仍找不到时用"选择文件"手动指定 CLI 绝对路径。找到多个同名命令时，界面列出各候选的绝对路径、版本与来源，必须手动选择一个（AgentPort 不会静默挑选）。

## CLI 升级后行为异常（恢复失败、状态不准）

- **现象**：升级某 CLI 后，"重启并恢复"报错或状态长期停留在 Unknown。
- **原因**：CLI 的参数或 Hook 事件随版本变化；AgentPort 按能力快照工作，不假定参数永远不变。
- **处理**：在设置页/诊断中心对该 Agent 执行"重新检测"，重新生成能力快照。未知版本的能力会优先降级（如恢复精度从 exact 降为 latest 并明示），而不会盲目猜测参数；若降级后仍不满足需求，请附上诊断摘要反馈。

## PTY/Host 启动失败

- **现象**："Session 未启动；没有后台进程被保留。"
- **原因**：可执行文件失效、目录权限不足或 Host 初始化失败。
- **处理**：查看启动失败条中的 stderr；重试启动；仍失败时到诊断中心导出诊断 ZIP 反馈。启动失败不会留下残留后台进程。

## Host 心跳丢失 / 连接中断

- **现象**："连接已中断，正在确认 Agent 是否仍在运行。"（连续 2 次心跳失败后进入失联重连）
- **原因**：Host 崩溃、机器重启或 Socket 失效。
- **处理**：
  1. 等待自动重连；
  2. 确认 Host 已退出后，Session 转为"已中断，可恢复"，点击"重启并恢复"；
  3. 注意恢复精度：Claude Code 始终精确（`--session-id` 启动即指定）；Codex/Kimi 在捕获到原生会话 ID 时精确，否则降级为恢复最近会话（`codex resume --last` / `kimi --continue`）并明示；Generic Shell 无法恢复，只会重开新 shell 并提示。
  4. AgentPort 不会在机器重启后伪装任务仍在运行，也不会自动执行恢复命令。

## Worktree 删除清理

- **行为**：删除确认框会列出未提交、已暂存、未跟踪、被忽略文件和关联 Session。
- **处理**：确认后 AgentPort 会自动解锁并强制清理托管 Worktree 目录、关联 Session、Git 与应用记录；dirty 或引用关系不会阻止删除。需要保留的内容必须先提交或移出该目录。若 Git 仓库已不存在，则直接清理 AgentPort 托管目录。

## 无法在系统终端中打开目录

- **原因**：未安装终端模拟器，或自动检测到的终端不支持其工作目录参数。
- **处理**：确认 `x-terminal-emulator`、`gnome-terminal` 或 `konsole` 可运行；也可在“设置 → 通知”填写终端可执行文件名或绝对路径。该设置不解析参数，会以目标项目目录作为工作目录启动；配置的命令启动失败时会直接显示错误，避免悄悄打开其他终端。

## 已结束 Session 没有历史或来源存在歧义

- **现象**：历史页显示“原生日志不可用”或“来源无法唯一确认”。
- **原因**：Generic Shell 没有原生会话日志；Agent 可能移动/删除了日志；或一次 AgentPort Session 在 `/clear`、fork、compact 后产生了多个原生 ID，而现有元数据不足以安全绑定。
- **处理**：确认对应 Agent 的原生日志目录仍存在。AgentPort 只读取经过 Provider 根目录与 Session ID/CWD 校验的文件，不会猜测候选文件。需要留档时，从历史页显式导出 Markdown/JSON。

## 升级后仍占用大量磁盘

- **现象**：应用数据目录中仍存在旧版 `sessions/*/output.log` 或 `sessions/*/runs/*/output.log`。
- **原因**：升级不会自动删除历史文件，避免在 Agent 原生日志不可用时造成不可恢复的数据丢失。旧正文 FTS 缓存会自动清空。
- **处理**：打开“设置 → 历史与存储”，查看每项大小、是否属于活动 Session、原生日志覆盖状态；只选择确认不再需要的项并执行二次确认清理。符号链接和活动 Session 日志不会被删除。

## Secret Service / Keychain 不可用

- **现象**："系统安全存储不可用，AgentPort 不会改用明文保存。"或 Secret 状态显示"已锁定/后端不可用"。
- **原因**：macOS Keychain 被锁定；Linux 上未运行 Secret Service（部分最小化或 headless 桌面）、D-Bus 不可达，或你取消了系统凭据授权。
- **处理**：
  1. 解锁系统凭据存储后重试；
  2. 无法恢复后端时，可在启动 AgentPort 前通过 Shell 环境注入变量（预设中列出变量名即可继承）；
  3. 或在预设中移除该 Secret 引用。
  4. 注意：AgentPort 没有明文文件回退，这是硬约束而非故障；依赖不可用 Secret 的 Session 会被阻止启动。

## 系统通知不弹出

- **现象**：状态变化时只有应用内未读徽标，没有系统通知。
- **原因**：系统通知权限被拒绝，或 Linux 桌面缺少通知服务。
- **处理**：应用内未读状态是可靠通道，不受权限影响。需要系统通知时，按设置页的指引开启：macOS 到"系统设置 → 通知"允许 AgentPort；Linux 确认 `notify-send` 可用且桌面运行通知守护进程。设置中的"通知"开关默认开启，但最终受系统权限控制。

## 状态显示"状态可能不精确"

- **现象**：状态图标旁显示中置信度与"状态可能不精确"。
- **原因**：官方 Hook 不可用时的正常降级——状态改由 PTY 启发式与进程事实判断。当前 Codex（0.144.5 无可验证的 Hook 注入机制）与 Kimi Code（0.27.0 无会话级 Hook 机制）默认处于该档；AgentPort 不会为了拿到高置信度而去修改你的全局 CLI 配置。
- **处理**：无需处理，属预期降级；CLI 未来版本提供会话级机制并重新探测后，状态会恢复高置信度。

## 提交问题反馈

反馈问题前请附上诊断信息（默认不含环境变量值与凭据）：

1. 诊断中心 →"复制诊断摘要"，直接粘贴到 Issue；
2. 或"导出诊断 ZIP"，连同复现步骤一起提交；
3. 说明平台（macOS 版本 / 发行版与桌面环境）、Agent 及版本、操作步骤与预期行为。
