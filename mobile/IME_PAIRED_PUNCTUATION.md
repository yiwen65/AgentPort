# 输入法自动补全字符导致后续输入中断（豆包 iOS）

## 现象（2026-09-19 用户报告）

iPhone + 豆包输入法，在 AgentPort mobile 终端里输入 `(` `)` 或引号之后，
继续输入其他文本时终端不再出现任何字符。

## 本机实测：机制已复现（适配层级）

真实 `@xterm/xterm` 5.5 + `installIosImeRouting`（iOS 归属适配层），
用合成 DOM 事件序列逐事件记录分支判定（复跑命令见
`/tmp/agentport-ime-probe/RESULTS.md`，探针源码
`/tmp/agentport-ime-probe/iosIme.probe*.test.ts`）：

| 变体 | DOM 序列 | 修复前 sent |
|---|---|---|
| V1 | 一次 `insertText` 报告 `(`，DOM 却变成 `()`、光标停在中间，之后照常打字 | `[]`（一个字都不发） |
| V2 | `(` 正常发出，随后补出的 `)` 把光标留在它前面，之后打字 | `["("]`，之后全空 |
| V3 | 输入法把光标跳过自己补出的 `)`，再打字 | `["(", "x"]`（自己恢复，但补出的 `)` 从未发出） |
| V6 | 弯引号 `“”` 光标在中间，之后打字 | `[]` |
| V9 | 无配对（对照） | `["(", ")", "x"]` |

第一处分歧：`reconcile()` 只接受**光标在 textarea 末尾**（`atEnd`）的编辑。
输入法把光标留在自己补出的字符前面时，`atEnd` 永远不会再成立，此后每次编辑
都判为 `unproven-edit` → 不发字节；而 `input` 监听仍在捕获阶段
`stopImmediatePropagation`，xterm 自己的兜底也拿不到事件 ⇒ 终端对之后的
输入完全无反应。次要缺陷：该状态下按退格，DOM 删除被判 `hardware-owned`
丢弃，但按键仍走 xterm 发出一个 DEL —— 抹掉一个终端其实没收到过的字符。

## 真机实测（部分）

在用户 Mac 上建了一个只记录字节的探针会话（raw 模式读 PTY，记录每个到达
Host 的字节块 + 1 Hz 心跳，`/tmp/ime-probe/capture.py`）。真机侧观察到：

- 中文（全角）模式打 `(` 时，Host 一次性收到 6 字节 `（）`（U+FF08 U+FF09），
  即**两个字符都被发送**，之后用户继续输入的文本也照常到达 shell
  （会话 `.zsh_history` 里出现完整命令行）。这一路没有复现"卡死"，只多发了
  输入法补出的那个 `）`。
- 探针在收到第一块数据后崩溃（作者自己的 bug：`bytes.endswith("\r")`
  传了 `str`），因此**半角 `(`、直引号 `"` 这条最可能触发故障的路径还没有
  真机字节证据** —— 修复后仍需在真机上按同样的顺序复测。

## 修复边界

`src/terminal/iosIme.ts` 增加 `ghosts`（输入法自己插入、用户没敲过的文本区间）：

- 只有"用户敲的"部分进入终端：一次插入中，光标越过的前缀算用户输入，光标之后
  的部分登记为 ghost。
- ghost 永不发送、永不计入 DEL（按 Unicode scalar 计数，仅统计已发送字符）。
- 只有**编辑区域之后没有已发送字符**时才映射这次编辑（终端是追加式的）；
  无法映射的编辑仍然放弃归属，但不再因此停止后续编辑的映射。
- 配对插入即使没有 `beforeinput`，只要 `(base, value)` 的切分唯一也可接受；
  切分有歧义时拒绝猜测。
- 退格：只有在已拥有区域内、且删除目标全是可安全回退的 scalar 时才由 DOM 接管；
  删除 ghost 不发 DEL。

不做的事：不按时间/整句去重，不重写 textarea 内容，不改组合输入与粘贴路径，
不为复杂字形推断删除次数。

## 验证

- 新增 8 项回归（`iOS IME text the user never typed`）。回到修复前实现时其中
  6 项失败，失败内容即为缺陷：配对后 `sent=[]`、配对后打字 `sent=["("]`、
  以及两处"为从未发送的字符发出 DEL"。修复后全部通过。
- Mobile 全量 455 项测试、真实 Chrome 渲染回归
  `mobile/scripts/test-terminal-touch.mjs`、`npm run build`（tsc + vite）通过。
- 真机部分见上：全角 `（）` 一路已实测，半角/引号一路待复测。

## 未验证与残留风险

- **豆包真机上产生的是哪条序列尚未逐事件确认**（缺 trace）：修复覆盖的是
  "输入法在光标后插入未输入文本"这一类；若真机走的是"组合输入不结束"
  另一条路径，本修复不覆盖。
- 若输入法把用户敲的收尾字符**吞掉**（overtype，不产生 DOM 编辑），该字符无法
  被证明，仍不会发送；终端会少一个字符（不会卡死，也不会多发）。
- ghost 区间只在适配层内存里跟踪，textarea 内容不再被重写。
